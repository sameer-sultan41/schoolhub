# Make the live E2E lane run, and repair the compose frontends

**Work tier:** 2

## Context

The `e2e-live` workflow (nightly and on dispatch) has failed every recorded run: 50 since
2026-09-05. No live journey has ever run on CI, including the timetable build-and-publish CUJ and
the cover API journey. No run has got past building images, so every step after that is
unexercised. These causes are stacked:

1. **MinIO images withdrawn.** Fixed by #124; e2e-live on its branch got past the pull.
2. **The frontend images have no `dev` stage.** `docker-compose.yml` builds the `dashboard` and
   `website` services with `target: ${FRONTEND_BUILD_TARGET:-dev}`, and `.env.example` sets
   `dev`. But `apps/{dashboard,website}/Dockerfile`, created in `f7511d7` (2026-08-28) as
   production builds, define only `deps`, `builder` and `runner`. #124's run stopped here (run
   39724265737: `target stage "dev" could not be found (did you mean deps?)`).
3. **CI never prepares the database.** `infra/scripts/seed-dev.sh` is what makes the stack
   usable, and e2e-live doesn't run it.
   - PgBouncer's `userlist.txt` is gitignored and generated by its step 3. Without the file,
     Compose bind-mounts a directory in its place and nobody can log in.
   - Migrations must run as `schoolhub_migrator` directly on Postgres (its step 6). The api
     service's own `migrate` runs as the app role, which can't create tables on a fresh
     database. The workflow's comment that "/healthz only ever answers once migrations have
     applied" is therefore wrong.
4. **The compose frontend services are stale, which matters for local dev.**
   - `NODE_IMAGE: node:24-alpine` is passed to `Dockerfile`s that read `NODE_VERSION`
     (`24-slim`), and `.env.example` pins alpine too.
   - The website gets `INTERNAL_API_BASE_URL` and `PUBLIC_CONTENT_TOKEN`, but
     `apps/website/src/lib/env.ts` requires `API_BASE_URL` and `WEBSITE_MACHINE_TOKEN`.
   - The dashboard's `/api/auth/*` rewrite (`apps/dashboard/next.config.ts`) targets
     `NEXT_PUBLIC_API_BASE_URL` (`api.localhost`). Inside the container that resolves to the
     container itself, so login can't work.
   - `.env.example` defaults `API_REPO_PATH` and `FRONTEND_REPO_PATH` to sibling repos that no
     longer exist. It also describes a `"prod"` frontend target, which doesn't exist (it's
     `runner`).
5. **The Playwright cache key is always `playwright-Linux-`** (doesn't fail the job).
   `require('@playwright/test/package.json')` fails from the repo root, because the package
   belongs to `e2e` only and is not hoisted. That is true before *and* after `pnpm install`:
   `frontend.yml`, which resolves it after install, logs the same empty key (run 39729201076).

**User decisions (2026-10-22):**
- Repair the compose frontends.
- CI serves the apps on the runner, as the PR lane does.
- Edit `infra/compose/.env.example`, the template only; nobody's `.env` is touched.
- Reuse `seed-dev.sh` for CI with a backend-only mode.
- The dashboard's auth proxy gets a server-only API URL.

## Approach

### 1. CI: the backend through `seed-dev.sh`, the apps through Playwright

- **`infra/scripts/seed-dev.sh`:**
  - New flag `--backend-only`, documented in its usage block. The last step becomes
    `dc up -d api celery-worker celery-beat` instead of `dc up -d`, so the compose frontends never
    start and claim 3000/3001, the ports Playwright's `webServer` binds.
  - Everything else is unchanged: `.env` from the example with random secrets, the userlist, the
    RLS assertions, migrate as the migrator, and `seed_dev_data` plus `seed_e2e_data`. It honours
    `E2E_LIVE_ADMIN_PASSWORD` already.
- **`.github/workflows/e2e-live.yml`:**
  - **Setup:** one step, which replaces the hand-written `.env` and `docker compose up`:
    1. `infra/scripts/seed-dev.sh --backend-only &`, saving its pid;
    2. `pnpm install --frozen-lockfile`;
    3. `pnpm --filter @schoolhub/e2e exec playwright install --with-deps chromium`;
    4. `wait "$pid"`, which fails the step under `set -e`.
  - **Steps removed:**
    - the separate `seed_e2e_data` step (seed-dev runs it);
    - "Wait for the dashboard and website to respond", because Playwright's `webServer` waits on
      each app's readiness probe, with a 300 s timeout.
  - **Kept:** the `/healthz` wait, with its comment corrected (seed-dev migrates first).
  - **Run step:** drop `E2E_NO_SERVER` and add `E2E_REAL_API: "1"`. The "Assert the live project
    has tests" listing keeps `E2E_NO_SERVER`.
  - **Browser cache: delete it**, with the "Resolve Playwright version" step.
    - Playwright's CI docs advise against caching browsers, and `--with-deps` installs OS
      packages a cache can't hold anyway.
    - `frontend.yml` has the same empty key. It is logged in `deferred-work.md` rather than
      changed here, since the PR gate's timing is its own decision.
- **`e2e/playwright.config.ts`:**
  - **New switch:** with `E2E_REAL_API=1`, `webServer` drops the `tenant-lookup-stub` entry and
    keeps `serve("dashboard")` and `serve("website")`. It's a literal `process.env` check, like
    `E2E_NO_SERVER`. Keeping the stub would fail: `:8000/healthz` is already answering, and
    `reuseExistingServer` is off on CI.
  - **Comment fix (L12):** the readiness comment says `/robots.txt` never calls
    `resolveTenant()`; `apps/website/src/app/robots.ts` does. Under `E2E_REAL_API=1` the probe
    depends on the real API, which is up by then.
- No API change. Checked: the default `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS` include
  `http://localhost:3000`, dev `ALLOWED_HOSTS` is `*`, and the real API 404s
  `/public/tenants/by-host` exactly as the stub does, so the website specs keep passing.

### 2. Local: repair the compose frontend services

- **`apps/dashboard/Dockerfile`, `apps/website/Dockerfile`:**
  - **Base image arg:** `ARG NODE_IMAGE=node:24-slim` and `FROM ${NODE_IMAGE}` for every stage,
    replacing `NODE_VERSION` and matching `apps/api/Dockerfile`'s `PYTHON_IMAGE`. The default
    image is unchanged, so `runner` builds the same.
  - **New `dev` stage:** `FROM deps AS dev`, with `NODE_ENV=development`,
    `NEXT_TELEMETRY_DISABLED=1` and no build. `deps` already enables corepack. Its comment names
    what asks for it, as the API's does.
  - **No `prod` alias.** `runner` is the deploy image and can't run under this compose file: its
    command needs pnpm over a bind mount, and `next build` needs `NEXT_PUBLIC_*` at build time.
    So the frontends support only `dev` in compose, and `.env.example` says so.
  - **Header comments:** reworded, since the images are no longer production-only.
- **`apps/dashboard/next.config.ts`:** the `/api/auth/*` rewrite reads a server-only
  `API_BASE_URL` first and falls back to `NEXT_PUBLIC_API_BASE_URL`, the split the website already
  has.
  - Compose sets `API_BASE_URL: http://api:8000/api/v1`.
  - The runner-served CI and PR lanes already set `API_BASE_URL` in `appEnv` to the same host as
    the public one, so nothing changes there.
  - `turbo.json` already declares `API_BASE_URL`.
  - **Not runtime config.** `next.config.ts` is serialized at `next build`, so for a standalone
    build the rewrite target is fixed at build time, like the `NEXT_PUBLIC_` value today. ADR-0026
    says so, and `deferred-work.md` records that an image can't be pointed at a different API
    per environment (`infra/AGENTS.md` rule 5).
- **`infra/compose/docker-compose.yml`** (both services):
  - `NODE_IMAGE` defaults to `node:24-slim`.
  - **`node_modules`:**
    - Keep the repo bind mount and the named root `node_modules` volume.
    - Add anonymous volumes for `apps/<app>/node_modules` and
      `packages/{ui,types,api-client,config}/node_modules`.
    - Add a named volume for the pnpm store at `/pnpm/store`. The Dockerfile's BuildKit cache
      mount is not part of the image, so without it every start would download everything.
  - **Command:**
    `sh -c "pnpm install --frozen-lockfile --filter @schoolhub/<app>... && pnpm --filter @schoolhub/<app> dev --hostname 0.0.0.0"`.
    - The filter keeps each container out of the other app's and `e2e`'s `node_modules`.
    - There's no duplicate `--port`; the `dev` scripts already pass it.
  - **Keeping `node_modules` current:** the filtered install at every start does it. After a
    rebuild, `-V` (renew anonymous volumes) is optional, because the root `node_modules` stays a
    named volume that `-V` doesn't renew.
  - **Website env:**
    - `API_BASE_URL: http://api:8000/api/v1`.
    - `WEBSITE_MACHINE_TOKEN: ${PUBLIC_CONTENT_TOKEN}` and
      `REVALIDATE_WEBHOOK_SECRET: ${REVALIDATE_SECRET}`, mapped in compose so existing developer
      `.env` files keep working.
  - **Dashboard env:** `API_BASE_URL: http://api:8000/api/v1` and
    `NEXT_PUBLIC_APP_URL: http://localhost:${DASHBOARD_PORT:-3000}`.
  - Drop the unread `INTERNAL_API_BASE_URL` from both, and fix the stale "Next.js 15" headers.
- **`infra/compose/.env.example`:**
  - `NODE_IMAGE=node:24-slim`.
  - `API_REPO_PATH=../../apps/api` and `FRONTEND_REPO_PATH=../..`, this monorepo's layout.
  - **Comments:**
    - The build target is `dev` or `prod` for the API, and `dev` only for the frontends in
      compose.
    - The stale "sibling checkouts" comment and the `schoolhub-srd` spec path are fixed.
- **`infra/scripts/seed-dev.sh`, ready banner:** under `--backend-only` it leaves out the
  Dashboard and Tenant-site URLs, and points at `pnpm` / Playwright instead.
- **`.github/workflows/infra-compose.yml`:**
  - **New step:** `docker compose build` for every service with a `build:` (api, celery,
    dashboard, website). A missing stage or a bad build arg then fails the PR that causes it.
  - **Path filter:** add what the images build from, so a lockfile-only PR can't break a `dev`
    image unseen:
    - `apps/{api,dashboard,website}/Dockerfile` (the frontend ones broke this in `f7511d7`);
    - the root `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` and `.npmrc`;
    - `apps/*/package.json` and `packages/*/package.json`;
    - `apps/api/{pyproject.toml,uv.lock}`.
  - **Header comment:** drop the stale claim that "the application images live in other repos".
  - **Pin checks:** `check "node:24-slim"` and `check "python:3.14-slim"`.
  - No repo-path override is needed once `.env.example` is fixed.

## Alternatives considered (why not)

- **CI runs the repaired compose frontends.** Rejected (user decision). `next dev` compiles each
  route on first request, so live journeys would hit compile latency the PR lane never sees, and
  CI would test a dev build, not the production one.
- **CI runs the `runner` image in compose.** Rejected. `NEXT_PUBLIC_*` values are inlined at
  build time, so it needs per-environment build args plus an override file, duplicating `appEnv`.
- **Copy seed-dev's userlist and migrate steps into e2e-live.** Rejected (user decision). That
  makes two setup paths to keep in step, and the RLS assertions in seed-dev's step 5 would not run
  in CI.
- **`extra_hosts: api.localhost:host-gateway` for the dashboard proxy.** Rejected (user decision).
  It leaves through the host's published port and depends on host-gateway support.
- **Map the env names in compose and leave `.env.example` alone.** Rejected for `NODE_IMAGE` and
  the repo paths. A `.env` value overrides a compose default, so the alignment wouldn't take
  effect. The website token names are still mapped in compose, so existing `.env` files keep
  working.
- **Raise the job's 30-minute timeout up front.** Not done. The first run that gets this far
  measures it, and any raise is a measured change with its reason (stop rule 2).

## Amendment (2026-10-22, after the change review)

- **Found by the change review:** PgBouncer can't read the userlist on a Linux runner.
  - `seed-dev.sh` wrote it with mode `0600` as the runner user (uid 1001).
  - The `edoburu/pgbouncer` image runs as `postgres` (uid 70).
  - A Linux bind mount keeps the owner and mode, so both seeds fail authentication.
  - Docker Desktop on macOS hides this, and seed-dev had never run on Linux before.
- **User decision:** `chmod 644`. The file holds SCRAM verifiers, not plaintext passwords,
  which stay in the `0600` `compose/.env`, and both files are git-ignored. This is the plan's
  one change to seed-dev beyond `--backend-only`.
- **Rejected:**
  - a Linux-only 644, because it makes behaviour differ by platform;
  - `auth_query`, because it's a larger change to `pgbouncer.ini` and the roles.
- **Smaller review findings applied:**
  - `e2e/AGENTS.md`;
  - the `tenant-lookup-stub.mjs` comment;
  - `||` for the proxy fallback;
  - three over-claiming doc wordings;
  - a trap that kills the background seed when an install fails;
  - the lesson renumbered to L17, because open PR #117 already has L16;
  - status docs that call the lane rebuilt, not proven, until a dispatched run gets past setup.
