## Deliberately NOT done

- **No `node_modules` locally.** `pnpm-lock.yaml` was generated with
  `pnpm install --lockfile-only` (resolution only) and is committed because CI uses
  `--frozen-lockfile`. Nothing was installed, built, linted, or tested locally — CI is the
  source of truth.
- **No E2E layer.** Jest only, no Playwright (team decision; the spec doc names Vitest +
  Playwright — this repo uses Jest and no E2E).
- **No generated API resource layer.** `packages/api-client` ships the transport core only;
  `students.list()`-style resources arrive with the OpenAPI generator.
- **No module screens.** Only the dashboard home exists. Students, fees, attendance, … are
  untouched.
- **No shadcn/ui CLI install.** `packages/ui` hand-implements the few components needed so far
  in the shadcn idiom (cva + tokens), with no Radix dependency yet.

## Start here next session

1. **CI is fully green** — lint, typecheck, 35 tests across 5 suites, both app builds, and the
   gitleaks scan. Keep it that way; it is the source of truth for pass/fail.
2. **Leave the two-TypeScript setup alone.** `typescript` is aliased to the TS 6 API for
   tooling and `@typescript/native` supplies TS 7's `tsc` — the arrangement the TypeScript 7
   release notes prescribe, because 7.0 ships no stable programmatic API. Pointing
   `typescript` at 7.x kills the whole lint layer and Next's type checking. Collapse to one
   TypeScript only after typescript-eslint supports the 7.1 API (#10940).
3. **Do not bump ESLint to 10.** It removes `context.getFilename()`, which
   `eslint-plugin-react` (bundled in `eslint-config-next`) still calls; every app lint task
   dies. Wait for an ESLint 10-compatible `eslint-plugin-react`.
4. **Decide the typed-routes question.** App code uses explicit prop types rather than Next 16's
   generated `PageProps`/`LayoutProps` globals, so `tsc --noEmit` works without a prior build.
   If the team prefers the generated globals, add `next typegen` to the `typecheck` script.
5. **Wire the OpenAPI generator** (`pnpm generate:api`) once the backend publishes its spec, and
   delete any hand-written resource shapes it replaces.
6. **Then build the first module screen** end-to-end (students list is the natural first) using
   `queryKeys.list()`, `DataTable`, and `<Can>` — it will prove the whole stack.
