# SchoolHub Frontend

Turborepo monorepo for the SchoolHub platform frontend: the tenant **admin dashboard** and the
multi-tenant **public school website renderer**.

Specification: <https://github.com/sameer-sultan41/schoolhub-srd> (`schoolhub-srd`). The docs
repo is the source of truth — see [`AGENTS.md`](AGENTS.md) for the context-map rule before
reading it.

**Picking the work up?** [`docs/STATUS.md`](docs/STATUS.md) records what is built, what is
deliberately missing, and where to start next. Keep it current in the same PR as your change.

## Layout

```
schoolhub-frontend/
├── apps/
│   ├── dashboard/        Next.js admin dashboard (authenticated, per-tenant)
│   └── website/          Next.js public renderer (Host-header tenant resolution, ISR)
└── packages/
    ├── ui/               shadcn-based shared components + the Tailwind v4 theme layer
    ├── types/            shared TS types (API envelope, errors, pagination, tenant, content)
    ├── api-client/       typed REST client — regenerated from the API OpenAPI spec
    └── config/           shared ESLint flat config
```

## Requirements

- Node.js 24 LTS (`.nvmrc`)
- pnpm 9 (`corepack enable && corepack prepare pnpm@9.15.0 --activate`)
- A running `schoolhub-api` (or a staging URL) for anything beyond static rendering

## Getting Started

```bash
pnpm install
cp .env.example .env          # then fill in the values
pnpm dev                      # runs every app through Turborepo
```

| App | Dev URL | Notes |
| --- | ------- | ----- |
| `dashboard` | <http://localhost:3000> | Sign in at `/login`; the auth guard lives in `src/middleware.ts` |
| `website` | <http://localhost:3001> | Needs a `Host` header that resolves to a tenant (see below) |

### Exercising multi-tenancy locally

The renderer resolves the tenant from the `Host` header — a wildcard subdomain
(`<slug>.<platform-domain>`) or a verified custom domain. Add hosts entries, or curl with an
explicit header:

```bash
curl -H 'Host: cityschool.schoolhub.local' http://localhost:3001/admissions
```

## Scripts (root, via Turborepo)

| Command | What it does |
| ------- | ------------ |
| `pnpm dev` | Runs every app in watch mode |
| `pnpm build` | Production build of both apps |
| `pnpm lint` | ESLint across all workspaces |
| `pnpm typecheck` | `tsc --noEmit` across all workspaces |
| `pnpm test` | Jest unit/component tests |
| `pnpm test:coverage` | Jest with coverage reporting |

Scope a command to one workspace with `pnpm --filter @schoolhub/dashboard <script>`.

## API Contract

The backend publishes **OpenAPI 3.1**; `packages/api-client` and the request/response types in
`packages/types` are regenerated from it in CI. A contract change that breaks the dashboard
fails frontend CI before deploy. Do not hand-edit generated surfaces — see
[`packages/api-client/README.md`](packages/api-client/README.md).

## Conventions

- TypeScript strict everywhere; no hardcoded brand colours (tenant branding → CSS custom
  properties); permission-gated UI via `hasPermission(user, 'fees.invoice.create')`.
- `kebab-case` files, `PascalCase` components, `use*` hooks, tests co-located as `*.test.tsx`
  (Jest + React Testing Library, wired through `next/jest` in the apps).
- Both apps were generated with `create-next-app` (Next 16, Turbopack, Tailwind 4, `src/`,
  `@/*` alias) and then customized; the Next.js-managed block at the top of each app's
  `AGENTS.md` is regenerated by `next dev` and must stay.

## CI

`.github/workflows/ci.yml` runs install → lint → typecheck → test, then a build matrix over
`dashboard` and `website`. CI is the source of truth for pass/fail.
